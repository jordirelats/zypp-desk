Getting started

Zypp Desk is a window for zypper, the program that installs, removes and updates software on openSUSE. Everything Zypp Desk does, it does by running zypper, and it always shows you the exact command.

Three ideas make it safe to use:

  • Nothing changes until you apply it. What you choose goes to the queue at the bottom of the window. You can look at it (Review the queue…), try it (Simulate the queue) and only then make it real (Apply the queue…).
  • Every question says what will happen in plain words, what it means for you, and the exact command underneath. Pressing Enter never starts a change: you have to choose the button that does it.
  • You can always see what zypper says. The terminal at the bottom (Show the terminal, in the sidebar) shows zypper's own output, and the panel next to it explains its warnings: how serious they are and what to do.

Changing the system needs the administrator password. Zypp Desk asks for it when it is needed and the computer remembers it for five minutes, so several steps in a row ask only once.

Start on the Home page: a big search field and cards that tell you whether there are updates, how your repositories are and what needs a look.

The queue: review, simulate and apply

Installing, removing, locking a package, adding a repository or importing a key: each of these is a change, and it waits in the queue until you apply it. The bar at the bottom shows how many there are and the commands they will run.

The colour of a button tells you what it does. A green button changes the computer now, always after a question; a button that only adds to the queue is never green, and it has To the queue: in front of it or says so in its label. Nothing in the queue changes the computer until you press Apply the queue….

When the queue removes packages, Apply the queue… simulates it first: zypper also removes, without asking, every installed package that needs one you remove. If it would remove packages you did not choose, the simulation says so in red, marks them as “not in the queue”, and its button asks before removing them too. In Packages, an orphan that something installed still needs cannot be ticked: it says who needs it.

  • Review the queue… lists the changes in the order they will run, in words. Each one has its own button to take it out of the queue. When a change needs another one (a program needs the repository it comes from, and the repository needs its key), the list says so, and Zypp Desk asks before you take out something others need.
  • Simulate the queue asks zypper what it would really do, without changing anything: what else it would install or remove, how much it would download, and whether there is a problem. If there is one, you can choose a solution in plain words.
  • Apply the queue… shows the changes once more and runs them. If a step fails, Zypp Desk stops there: what was done stays done, and the rest stays in the queue to try again.
  • Empty the queue takes every change out of the queue. It undoes nothing, because nothing has changed yet.

Simulate the queue only tries the package changes: changes to repositories, locks, languages and Flatpak apps have no dry run, and they run only when you apply.

Keeping the system up to date

openSUSE Tumbleweed gets a new version every few days. On the Updates page you find:

  • Your routine: the steps you usually run to update, for example refresh the repositories, download the updates, then install them. Update everything…, with the number of updates (for example Update everything (97)…), runs them one after the other and shows each step. While it runs, Stop after this step lets the current step finish and runs none of the rest: the button then says Will stop after this step, and the terminal tells you what will not run. Edit the routine… changes the routine with buttons, or as text, as you would type it in a terminal.
  • What there is to update: packages from the repositories, Flatpak apps, programs from the web and firmware, with a box to tick each one. Mark all and Unmark all, under the list, tick or untick them all at once. The card on the right tells you about the package you choose. The buttons under the list act only on what you ticked, and their label says it: for example Simulate only digikam or Put digikam in the queue.
  • The list shows what the computer knew the last time the repositories were refreshed: Look again reads it again. Refresh the repositories first asks every repository for what is new (with the administrator password), then looks again.
  • Simulate updating everything…: the full upgrade of Tumbleweed (zypper dup) in its own window, with its options.

Your routine updates the whole system: it does not look at the ticks. So when you have ticked some rows and left others unticked, Update everything… first asks Update the whole system? There, Not yet changes nothing; the button with the name of what you ticked, such as Only digikam, puts only that in the queue and asks you before applying it; and Yes, update everything runs the routine.

Proposed routines

In the routine editor, Proposed routines… shows a few ready routines, each with what it does, why, and the line it makes in a terminal. The first one is made for this computer: besides updating the system, it updates the Flatpak apps if you have any and the firmware if fwupd is installed, removes old kernels and downloaded packages if the disk is short of room, and tells you at the end which programs need a restart. The others are the usual one (download everything, then install only if everything was downloaded), one that only downloads, and a quick one. The one you choose goes into the editor, where you can still change it; nothing is saved until you press Save the routine.

A big update

When an update is big, or the new Tumbleweed came out less than a day ago, Zypp Desk asks whether it is worth waiting. It tells you how big it is, how new the version is and whether the computer is on battery. You can update now (Update everything now), Only download the update (installing it later is much faster), or choose Remind me tomorrow: the icon next to the clock will tell you.

Little room on the disk

If the update does not fit on the disk with room to spare, Zypp Desk offers to free space first (packages kept from earlier downloads, old kernels) and to update in parts. Each part is a normal zypper update of some packages, downloaded completely before it is installed: if a download fails, nothing of that part is installed, and the system stays as the previous part left it. A normal upgrade finishes what is left. Before anything is installed, Zypp Desk tries every part with zypper: a package whose update needs a decision waits for that normal upgrade at the end, and the question tells you which.

Installing and removing programs

  • Type a name in the search field of Home or Packages. Packages can search the descriptions, what a package provides or needs, its files, and the lists of orphaned or unneeded packages.
  • Applications shows the programs you have, wherever they come from (a repository, Flatpak or the web), and the ones with an update. Discover by theme shows the catalogues of openSUSE and Flathub by category.
  • Mark several with the boxes of the list (or of Discover by theme) and install, remove or lock them at once with the band that appears under the list. Mark all ticks every result.
  • The card of a package has its information, its versions (you can install an older one), what it needs, its files and its changes.
  • Remove… asks whether to also remove what only that program needed. Zypp Desk lists those packages first, so you see what goes.
  • Lock keeps a package as it is: zypper will not update or remove it until you unlock it in Locks.
  • Flatpak has the Flatpak apps, their updates, their remotes and their permissions. They go to the same queue.
  • Web apps, in Applications, are the sites your browsers installed as apps (Chrome, Chromium, Edge, Brave, Vivaldi, Opera, and Firefox with the PWAsForFirefox extension). The browser installs and updates them; Zypp Desk shows those of every browser together and opens them. To remove one, Zypp Desk opens the browser's own page of apps, because only the browser can remove it for good. If its browser is no longer installed, its menu entry does not work any more, and Zypp Desk can move it to the trash.

If the program is not in your repositories, Search online… looks for it in the openSUSE Build Service, Fedora COPR and Flathub, and explains how much you can trust each source.

Protecting an app

The buttons of a card in Applications say the program's name when there is room for it, for example Protect digikam…; otherwise they say Protect it…, the form used here.

Protect it…, on the card of an application in Applications, is for a program you never want to lose by mistake: Zypp Desk asks first, and while the app is protected, the queue refuses to remove it, from any page. Nothing else changes, and it still gets its updates. Stop protecting it takes the mark away.

A Flatpak app can disappear from its remote when nobody maintains or distributes it any more. Save a copy… saves the installed app as one .flatpak file (flatpak build-bundle), so that you can install it again from that file even when the remote no longer has it. What it needs to run (its runtime) still comes from Flathub.

AppImages

An AppImage is a whole program in one file: you download it from its maker and open it, without installing anything. zypper does not know AppImages, so Zypp Desk looks for them in the usual folders (~/Applications, ~/AppImages, ~/bin, ~/.local/bin, /opt and your Downloads folder) and among the menu entries, and the AppImage filter of Applications shows them. They are your own files: they never go through the queue, and nothing here needs the administrator password.

Zypp Desk reads the name, the version and the icon from inside the file, without running it. For that it needs unsquashfs, from the package squashfs; without it, it shows the file's name.

  • Open it starts the program as you. If the file is not executable yet, Zypp Desk asks first. It never runs an AppImage as administrator: open only AppImages from makers you trust.
  • Add it to the menu gives it a menu entry with its own name and icon. Remove it from the menu… moves the entry and its icon to the trash, and leaves the program where it is.
  • Look for a new version asks GitHub for the newest release, only when you press it. Most AppImages do not say where they are published: then Zypp Desk asks you for the address of the project on GitHub, and Change where to look… changes it later. If the file names another site, the button opens it in the browser.
  • Get the new version… downloads it next to the one you have (as a .new file) and checks it: with the SHA-256 that GitHub publishes, when there is one, and that it really is an AppImage. Then Zypp Desk asks before it takes the old one's place, with the same name, so that the menu entry keeps working.
  • The old version stays beside it as a .old file until the new one has opened once from Zypp Desk; then it goes to the trash. Until then, Back to the previous version… puts the old one back.
  • Protect it… works as for any other app, and Remove it… moves the file, its old version, its menu entry and its icons to the trash. Its settings and data in your home folder stay.
  • Add an AppImage…, at the top of the page, takes a file you downloaded, moves or copies it to ~/Applications, makes it executable and puts it in the menu.

An AppImage in a folder only the administrator can change (in /opt, for example) can be opened, but not updated or removed from here. A menu entry whose file is gone is marked as an orphan: Remove it from the menu… clears it.

Programs from the web and .rpm files

Some programs are published only as files on their web site or on GitHub. In Programs from the web Zypp Desk follows them: it looks for new versions, downloads them, checks them (the signature, or the checksum the author publishes) and puts them in the queue. After they are installed, the files go to the folder you chose, which can be a local zypper repository.

You can also open a downloaded .rpm file with Zypp Desk (from the file manager, Open with Zypp Desk). It tells you who signed it, what it needs and what it would replace, before anything is installed.

Programs made for Fedora

Some .rpm files are made for Fedora and ask for things by their Fedora names. When openSUSE has the same thing under another name, Zypp Desk shows you the list (Fedora name, openSUSE name, why) and can make a small bridge package that tells zypper they are the same. The bridge has no files; it is made on your computer and is listed in Programs from the web, which tells you when it is no longer needed. If something has no openSUSE equivalent, Zypp Desk says which and makes no bridge.

Repositories and signing keys

A repository is a place zypper downloads packages from. In Repositories you can enable or disable them, change their priority (a smaller number wins when the same package is in several), check which ones do not answer, change their address, and ask Zypp Desk to propose an order.

Some programs made for Fedora leave their repository in /etc/yum.repos.d, where zypper does not look, so they would never update. Zypp Desk notices it and offers to add the repository to zypper, with its key. If you chose Do not add it, More → Show the hidden repositories for Fedora brings it back.

A signing key proves who made a package or a repository. In Signing keys you see the keys your computer trusts, whose they are and when they expire, and you can import a new one from a web address, a file or its fingerprint, comparing it with the one the vendor publishes. Only trust a key from a source you trust: a key lets its owner install anything on your computer.

Services are lists of repositories kept by someone else (openSUSE keeps the Tumbleweed ones).

Languages and locks

Languages

Many programs bring their translations in separate packages (their -lang packages, dictionaries and spell checkers), and zypper installs them only for the languages it was asked for. If your computer is in a language zypper was never asked for, those packages never come, and parts of your programs show in English. When that happens, Home says so and offers to add the language of the computer with one button: it goes to the queue.

Languages has every language zypper knows. The ones you have shows those zypper was asked for, All shows them all, and the search field finds a language by its name or its code. Tick a language to add it, or untick it to remove it: the change goes to the queue (zypper addlocale or removelocale), and nothing happens until you apply it. The card on the right tells you what it would bring: how many translation packages for the programs you have, and which dictionaries.

  • When a language is added, zypper installs its translations for the programs you have, and from then on for those you install.
  • When a language is removed, its translations go; the programs stay, in your other languages.
  • English is always there, because the programs are written in it. The language of the computer, once added, cannot be unticked here.
  • This page does not change the language of the windows: that is chosen in the settings of your desktop.

Locks

A locked package is never installed, removed or updated by any zypper command until you unlock it. Locks lists your locks with the icon of each package. The card on the right tells you which version you have, whether a newer one is waiting, which versions and which repository the lock covers, and lets you unlock it. Locking and unlocking go to the queue, like any other change.

  • Lock a package… searches for packages: tick several and lock them at once. A name with wildcards, like vlc-*, locks every package whose name matches, also the ones that come later.
  • Clean the useless locks… removes the locks that no package matches any more, after a question.
  • When you choose to update the rest and leave some packages as they are (see When something goes wrong), Zypp Desk locks them. Those locks are marked as temporary, with their date. A band at the top tells you when their repository has published again, so that you can probably unlock them, and its button (for example Put the 3 unlocks in the queue) puts the unlocking of them all in the queue at once.

Moving to another computer

When you change computers, Zypp Desk can take your software with you in one file. On the old computer, choose Save this computer's software…: in Settings, on the card Move to another computer, or at the bottom of Home. It saves a file ending in .zdesk with what you leave ticked:

  • Repositories and keys: the enabled repositories with their priorities, and the signing keys they use.
  • The packages you chose, not those installed only because others needed them: zypper brings those back by itself.
  • Flatpak apps, with their remotes, and the Programs from the web that Zypp Desk follows.
  • Locks, languages, the routine and the zypp.conf settings, and the apps you protected.
  • A list of what to do by hand: AppImages, web apps, programs with their own installer and packages installed from a file. They cannot be installed by themselves, so they go on a list.

The file holds no passwords and none of your documents: only the list of your software and where it comes from. The keys in it are public keys, which anyone can download. Some things are left out on purpose:

  • kernels, firmware, microcode, drivers and the boot loader: they belong to the hardware and the installation of each computer, and the new one has its own;
  • a repository whose address has a user name, a password or a token: it goes on the list by hand, without its address;
  • temporary locks (those you get when you update the rest and leave some packages as they are), and packages from a local folder that Programs from the web does not follow.

On the other computer

Copy the file to the other computer and double-click it: it opens with Zypp Desk. You can also choose Open another computer's file…, in the same places. Zypp Desk compares the file with this computer and shows what it would do: the repositories to add, with their keys and fingerprints, the packages and Flatpak apps to install, the locks and languages to add, and how much is here already. Choose the repositories…, Choose the packages… and Choose the apps… let you untick some of them. The button that says how many changes there are, for example Put the 312 changes in the queue, adds everything to the queue, where you review, simulate and apply it like any other change. Until you apply it, nothing changes.

  • Your routine, zypper's settings (zypp.conf), the protected apps and the programs from the web only change if you say so. Before anything goes to the queue, a question shows each of them as it is now and as it would be: tick the ones to change. zypp.conf goes to the queue with the rest; the others change as soon as you answer.
  • By hand lists what Zypp Desk cannot do for you, each with what to do: download an AppImage or an installer again from its maker, install a web app again from its browser, copy a folder of programs, add a repository that needs a password, install a Flatpak app from the copy you saved. Copy the list copies it, to keep it at hand.
  • Packages that are not in the repositories of this computer, or that are locked here, are left out, and the window says which: one of them would stop the whole install.
  • Some changes have to wait: the packages of a repository that is only added now, and the locks of packages that are installed now. After you apply the queue, open the file again, and Zypp Desk adds what is left.
  • If the file comes from another version of openSUSE, or from a computer with another kind of processor, the window warns you: some repositories or programs may not fit.

Open only a file you made yourself, or one from someone you trust: its repositories and keys let zypper install programs from them as administrator. Zypp Desk checks everything in the file, and leaves out what does not pass, before it shows you anything.

Health check

At the top of Maintenance, Zypp Desk looks at the software of this computer and tells you what is worth a look, the most important first. Each finding has a sentence that explains it and, under Details, the names. Looking changes nothing: a finding's button opens the right page, or asks a question and puts the changes in the queue, which shows you the exact commands. Check the computer again looks again, for example after you have installed or removed something.

What it can find:

  • Firmware for hardware you do not have. openSUSE installs the firmware of every possible device, often close to a gigabyte. Each firmware package says which devices it is for, so Zypp Desk keeps what this computer uses and offers to remove the rest, on the Drivers page.
  • Apps no longer maintained. A Flatpak app whose developers have stopped gets no more updates, and Flathub may stop offering it. Protect it and save a copy in Applications, so that you do not lose it.
  • Packages from another vendor. They came from a repository you no longer have, or that no longer has them, and zypper does not update them on its own. Zypp Desk offers to install them again from the repository you have; when it only has older versions, it is better to leave them as they are.
  • Repositories with weak checks. Nothing from them is checked against a signature, or their list of packages comes unsigned over plain http. A signature proves that what you install comes from who it says.
  • Expired keys. A key a repository signs with has expired, or expires soon. Usually the project renews it, and zypper takes the new date when it refreshes; if refreshing shows a key error, import the new key in Signing keys. Expired keys that no repository uses can be removed there.
  • Packages that no repository has. They get no updates any more. Most are leftovers of programs that something else replaced: look at them before you remove them.
  • Apps installed twice, as a package and as a Flatpak app. They take room twice and show twice in the menu: keep the one you use.
  • What takes most room: the biggest packages, the Flatpak apps, the downloaded packages and the old kernels. Each name takes you to where it can be removed.

The checks that find nothing are listed together in one green line. Under the findings are the usual maintenance tasks (see When something goes wrong).

Drivers

Drivers shows the parts of this computer (graphics, Wi-Fi and Bluetooth, network, sound, webcams, printers), each on a card with the driver it uses and whether that driver is free. Most drivers are free and part of the kernel: then the card says All good, and there is nothing to do. The other marks:

  • There is a better driver: a proprietary driver works much better than the free one, above all with NVIDIA cards.
  • Firmware missing or Can be better: the driver can use a package that is not installed (firmware, the processor's microcode, video decoding in the card).
  • No driver: no driver is using the device.
  • Optional: a driver exists, but it is old, and the free one keeps working.
  • Good to know: something worth knowing, with nothing to do.

The button of a card only puts changes in the queue, after a question that says what each package is, where it comes from, whether it is proprietary and what happens with Secure Boot, with the exact commands. Nothing changes until you apply the queue, and the driver starts working after the next restart. If you plug in a dock or an adapter, the page looks at the hardware again when you come back to it; Look at the hardware again does it at once.

NVIDIA

With an NVIDIA card, Linux starts with nouveau, a free driver that is slow with most cards. Zypp Desk proposes the NVIDIA driver made for your card:

  • Recent cards (GeForce GTX 16, RTX 20 and newer): the series G07. Its kernel part is open source, comes from openSUSE's main repository and is signed by openSUSE, so it starts with Secure Boot on, with nothing to enroll. The rest (graphics libraries, video decoding, CUDA, settings) is proprietary and comes from NVIDIA's repository for openSUSE. If you do not have that repository yet, Zypp Desk adds it with NVIDIA's signing key, after checking that the key is the one it knows.
  • Older cards (Maxwell, Pascal and Volta: the GeForce GTX 750, 900 and 10 series): the series G06, all from NVIDIA's repository. Its kernel part is built on your computer when it is installed, which brings the compiler and the kernel's development files (a few hundred MB), and it is signed with a key made on your computer.
  • Very old cards: NVIDIA's old series still exist, but NVIDIA no longer updates them, and they only work in an X11 session. They are marked as optional; nouveau keeps working.

With Secure Boot on, a driver signed with a key made on your computer needs one step at the next start: a blue screen (MokManager) asks to enroll the key. Choose Enroll MOK, then Continue and Yes, and type the root password; the keyboard there is English (US). If you skip it, the computer starts with nouveau, and you can enroll the key at a later start.

Broadcom Wi-Fi

Some Broadcom Wi-Fi cards work with no free driver. For them, Zypp Desk proposes Broadcom's driver wl, from openSUSE's non-free repository (repo-non-oss): Broadcom's licence does not let it be free software, but openSUSE signs it, so it starts with Secure Boot on. If that repository is disabled, the queue enables it first. wl switches off the free Broadcom drivers, so Zypp Desk does not propose it when another device of this computer uses one of them.

Missing firmware

Many devices need firmware: a small program that their driver loads into the device when it starts. When a device can use a firmware package that is not installed, its card says so and has a button to install it from your repositories. If, at start, a driver asked for firmware it did not find, a card tells you which package has it. When no package has it, the card says that too: some drivers ask for a newer file first and then use an older one, so if everything works, it does not matter.

Not needed for this computer

At the end of the page, Zypp Desk lists what is installed for hardware this computer does not have, in groups: firmware for devices it does not have, microcode for the other make of processor, graphics and Wi-Fi drivers for other cards, tools for virtual machines, and printer drivers. It only lists what it is sure nothing here uses: nothing that a device of this computer, a loaded driver or another installed package needs, and nothing locked or protected. Stays says what stays and why: for example the firmware your devices use and, just in case, the firmware of devices that are often plugged in later (docks, USB network adapters, cameras).

  • A group is ticked when removing it is safe. Printer drivers, and drivers for USB devices that may simply not be plugged in now, are unticked: keep them if you might use one.
  • Remove the packages… shows what goes and the exact commands. Put it in the queue puts the removals in the queue; Put it in the queue and simulate also simulates the queue at once.
  • openSUSE installs all the firmware through one package, kernel-firmware-all, which the kernel recommends. When it goes, Zypp Desk also locks it: otherwise every new kernel would install it again, and all the firmware with it. The lock is in Locks, where you can remove it.
  • If one day you plug in a device that needs a package that is gone, this page shows it on the device's card, with a button to install it again.

When something goes wrong

  • A dependency problem: zypper cannot do what you asked without changing something else. Zypp Desk shows each problem in words with the solutions zypper offers, and recommends the one that changes least. When there are many, it first groups them by cause: often a repository built on top of Tumbleweed (VideoLAN, Packman) has not been rebuilt for the new version yet, and the problems go away by themselves in a day or two. You can wait and be reminded, update the rest and leave those as they are, or look at them one by one.
  • A file is not found while downloading: right after a new Tumbleweed version, the mirrors take a few hours to copy it. Try again in an hour.
  • Something broke after an update: History shows what changed in each update and, when the system makes snapshots (snapper), lets you undo the changes or go back to the system as it was.
  • A warning you do not understand: the panel next to the terminal explains it, says how serious it is and what to do.
  • Maintenance checks broken dependencies, removes old kernels, cleans the cache and tells you which programs still use old files and whether the computer needs a restart.

Notifications and settings

A small icon next to the clock tells you when there are updates. It starts when you log in; you can turn it off, or change how often it looks, in Settings. Zypp Desk installs a timer that refreshes the repositories every six hours, so the count is up to date. It never installs anything by itself. If you turn it on in Settings, it also downloads the next update in advance, only when the computer is plugged in and not on a metered connection (a phone hotspot).

Settings also has the options of zypp.conf (recommended packages, how many kernels to keep, connections per download…), the terminal, and which program opens .rpm files. The folder for programs from the web is changed in Programs from the web (Change the folder…).

Zypp Desk speaks English, Catalan, German and French. To translate it into your language, see TRANSLATING.md.

Own installers and Expert

Programs with their own installer

Some programs are neither RPM packages nor Flatpak apps: they install with their own installer (a .sh, a .run, or a .tgz with an install script inside). zypper does not know them, so nobody updates them. Own installers finds them in your folder, in /opt and /usr/local, and among the menu entries that belong to no package, and tells you where each one is and how much room it takes. Nothing on this page runs as administrator.

  • Uninstall it… runs the program's own uninstaller, if it has one, as you, in a terminal window where you can answer its questions. If it has none and it is in your folder, the button says Move it to the trash…: Zypp Desk moves its folder, menu entries and icons to the trash, and you can bring them back from there.
  • A program installed for the whole computer (in /opt or /usr/local) needs the administrator password to be removed. Zypp Desk does not do it: How to remove it… explains why and gives you the commands to run in a terminal.
  • Run an installer… runs the installer of a program you downloaded (a .sh, a .run, or a .tgz or .zip with an installer inside; an archive is unpacked into a folder of Zypp Desk's own). Zypp Desk asks before running it, and runs it as you, without the administrator password, in a terminal window. When it ends, Zypp Desk notes what it created, so that it can remove the program later even without an uninstaller. Nobody signs these installers: run only the ones you downloaded from the program's own website.
  • Menu entries whose program is not there any more are shown as left behind, and Zypp Desk can move them to the trash.

Expert

Expert is for those who know zypper. It has every zypper command, with the options that zypper's own help gives (in English). On the left are the most used commands by group, and the last row of the list shows them all; on the right, the form of the chosen command and the exact command it will run. You can also type a line as you would in a terminal, for example zypper se vlc; you do not need sudo.

  • Commands that only read (searches, information, the lists of repositories, packages or locks…) run as you, without the password, and show their output in the terminal.
  • Commands that change the system ask first, in words, and then ask for the administrator password. They always run with -n: nobody can answer zypper here, so it takes its default answers. When a command has a dry run, Simulate this command shows what it would do. Installs, removals, locks, languages and repository changes can also go to the queue, with Put this command in the queue.
  • Some lines are refused before anything runs, and the message says why: more than one command at a time (;, &&, |, >), anything that is not zypper, commands that wait for you to type (zypper shell), commands the administrator helper does not run, and options that point zypper at another root, configuration, cache or repository folder, or that add repositories or trust keys on their own (--root, --plus-repo, --gpg-auto-import-keys…).
